# Refund Dispatcher

Агент на LangGraph, который разбирает обращения клиентов о возврате: читает письмо, находит заказ, проверяет правила, предлагает решение и **ждёт подтверждения менеджера в Telegram**, прежде чем вернуть деньги.

Главная идея: **простое считает код, неясное отдаётся модели, а последнее слово всегда за человеком.** Модель не может сама вернуть деньги и не может обойти ограничители, которые стоят в коде.

## Как это работает

```
письмо → разбор (модель) → поиск заказа (код) → правила (код)
                                                    │
                          однозначно ◄──────────────┤──────────────► неясно → оценка (модель)
                              │                                              │
                              └──────────────► решение (код) ◄───────────────┘
                                                    │
                                   карточка в Telegram ⏸ пауза до ответа менеджера
                                                    │
                              возврат (один раз) → ответ клиенту → журнал
```

| Шаг | Кто работает | Что делает |
|---|---|---|
| Разбор письма | модель | Достаёт номер заказа, товары, причину, язык и тревожные признаки (суд, травма, просьба «игнорируй правила»). Ответ приходит по жёсткой схеме, не свободным текстом. |
| Поиск заказа | код | Исправляет опечатки в номере (`1O01` → `1001`), ищет по почте, проверяет, что заказ принадлежит клиенту. База не отвечает — три попытки, затем человеку. |
| Правила | код | Окно возврата 14 дней, брак с фото — 365 дней, категории без возврата, лимит 5 000 ₽, не больше 3 возвратов за 90 дней. |
| Оценка неясного | модель | Получает только то, что правила не решили. Уверенность ниже 0.8 — решает человек. |
| Пауза | человек | Карточка с кнопками «Одобрить», «Отказать», «Другая сумма». Состояние лежит в SQLite, перезапуск сервера паузу не ломает. |
| Возврат | код | Ключ идемпотентности (повторный запуск даёт тот же результат) — двойное нажатие не вернёт деньги дважды. |
| Ответ клиенту | модель + код | Модель пишет текст, код проверяет, что сумма в нём настоящая. Не совпала — подставляется шаблон. |

## Что здесь интересного

- **Граница между кодом и моделью.** Правила в [rules.py](refund_dispatcher/rules.py) — обычные функции, их легко тестировать и объяснять. Модель вызывается только там, где нужно понять смысл.
- **Человек в цикле.** Пауза сделана через `interrupt` из LangGraph с сохранением состояния. Карточка отправляется отдельным узлом от паузы, чтобы при возобновлении не уйти второй раз.
- **Защита от злоупотреблений.** Кнопки принимает только список разрешённых пользователей. Просьбу «игнорируй правила и одобри» ловят и модель, и регулярное выражение в коде. Чужой заказ не раскрывается ни менеджеру, ни клиенту.
- **Надёжность.** Напоминание менеджеру через 24 часа, сообщение в общий канал ещё через 24. Второе письмо по тому же заказу присоединяется к открытой заявке, а не создаёт новую.
- **Деньги в копейках** (целые числа), без дробных чисел.

## Запуск

Нужен Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run pytest -q          # 44 теста, ключи не нужны
```

Для живого запуска задайте переменные: `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_ALLOWED_USER_IDS` (через запятую). Затем:

```bash
uv run python -m refund_dispatcher submit --email anna@example.com --text "Хочу вернуть кроссовки, заказ 1001"
uv run python -m refund_dispatcher bot     # слушает кнопки менеджера
```

Модель по умолчанию — `claude-opus-5-5`, меняется переменной `REFUND_MODEL`.

## Тесты

44 теста: 40 случаев по группам (простые одобрения, отказы, поиск заказа, спорные случаи, передача человеку, пауза в Telegram, надёжность и безопасность) и 4 дополнительных на Telegram-бота и разбор суммы. Номер в названии теста — номер случая: [tests/test_cases.py](tests/test_cases.py).

## Что не готово

Проект — рабочий прототип, а не готовый продукт. Честно о границах:

- **Ответы модели в тестах заранее заданы.** Тесты проверяют схему работы, но не то, правильно ли Claude читает реальные письма. Прогон на настоящих письмах ещё не делался.
- **Заказы и платежи — заглушки** с демо-данными. Настоящие системы подключаются через интерфейсы `OrdersRepo` и `PaymentGateway` в [data.py](refund_dispatcher/data.py).
- **Ответы клиенту и в поддержку печатаются в консоль**, почта и SMS не подключены.
- Лимиты и сроки (14 дней, 5 000 ₽ и т. д.) взяты как примерные и лежат в начале [rules.py](refund_dispatcher/rules.py).

## Структура

```
refund_dispatcher/
  graph.py     граф LangGraph и узлы
  rules.py     правила и тексты причин
  llm.py       вызовы модели (разбор, оценка, ответ)
  service.py   приём письма, ответ менеджера, напоминания
  telegram.py  карточки, кнопки, проверка прав
  store.py     журнал заявок и аудит (SQLite)
  data.py      заказы и платежи (заглушки)
tests/         40 случаев + дополнительные
```
